- D-019 · 2026-10-08 · 1 · **MVSEC evaluation protocol** (`configs/eval_mvsec.yaml`), following EV-FlowNet's evaluation code (daniilidis-group/EV-FlowNet @cf801ef, `src/test.py`, `src/eval_utils.py`) and E-RAFT (uzh-rpg/E-RAFT @c58ce05, `config/mvsec_20.json`): (a) region = central 256×256 crop (rows 2–257, cols 45–300 of 260×346); outdoor additionally excludes full-image rows ≥ 192 (EV-FlowNet zeroes rows ≥ 190 *of the crop*; E-RAFT uses ≥ 193 — that variant is only used to reproduce E-RAFT in Phase 4); (b) valid_gt = GT finite and |GT| > 0, AND events-in-window (sparse = pixel has ≥ 1 event in the window). Deliberate deviation: EV-FlowNet's `test.py` rescales the count image to uint8 (`count·255/max`) before `> 0`, which drops pixels with count < max/255; we keep every pixel with an event, as E-RAFT's sparse mode and tudelft/event_flow do; (c) per-window mean, then mean over windows; windows with 0 valid pixels are skipped and counted; (d) outdoor_day1 window = [1506118120.162041, 1506118137.667426] Unix s = span of GT fields 4356–4705 of `outdoor_day1_gt_flow_dist.npz` (`timestamps[4356]..timestamps[4706]`, 222.97–240.47 s after the first event; APS frames 10164–10960 for dt=1, 797 windows; 10164–10957 for dt=4). The field indices are E-RAFT's (`mvsec_20.json` `range(4356, 4706)`), but the APS windows are our construction: E-RAFT uses `align_to: depth` and `timestamps_depth[i] == timestamps_flow[i+1]`, so it pairs field i with events over [flow_ts[i+1], flow_ts[i+2]] (span 1506118120.212090–1506118137.717505, 50 ms later), dense mask, hood rows ≥ 193. That pairing is declared in `reproduction_eraft` for Phase 4, which must also define "E-RAFT's own evaluation" (the E-RAFT repo ships no metric code). Correction made after the Phase 1 flow-metric-verifier review; indoor_flying1–3 = every APS window inside the GT time span; stride 1 frame for dt=1 and dt=4; (e) GT for an APS window = EV-FlowNet's propagation (positions advanced through successive 20 Hz GT fields with nearest-pixel lookup, partial first/last intervals scaled linearly, a pixel whose looked-up flow is exactly 0 or that leaves the image is invalid; if the window is shorter than the GT interval, the GT is scaled by dt/gt_dt). EV-FlowNet's code is under a non-commercial, no-redistribution licence, so **no code is copied**: `io/mvsec.py` re-implements the published algorithm. Checked by the verifier against EV-FlowNet's `estimate_corresponding_gt_flow` on real indoor_flying1 (40 windows each): dt=1 max |diff| 1.2e-4 px; dt=4 a few pixels per window differ (µs rounding of timestamps flips nearest-pixel lookups), ≤ 2.8e-4 px on any per-window mean. · Plan §1.3 "fix one, record it"; verifier item 3 (dt=4 accumulated, not ×4). · configs/eval_mvsec.yaml, src/evflow/io/mvsec.py
